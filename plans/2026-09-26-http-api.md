## 1. 设计摘要

- 前缀：`/v1`；JSON；camelCase；本机 Bearer token。
- 表面：**REST 实体 CRUD + 少量 action**（打标、关系重排、关系批量创建、标签邻域）。
- 标识：**双轨** — 管理路径以 Guid 为主；常用入口同时接受 alias / uri。
- 打标：`POST /v1/resources/tags` 批量 `add` / `remove`；未知 uri **隐式建资源**；`createMissing: true` 时未知别名 **自动建标**。
- 网状标签：边表 CRUD + `GET /v1/tags/{id}/neighbors`（一跳邻域）；查询侧仅 `expand=child`（`related` 不进集合展开）。
- 响应：**统一信封** `{ status, message, data }`（成败同构外壳；见 §2.2）。
- 查询语法细则 → [查询语言细则](./2026-09-26-query-language.md)；本契约定路由、JSON 骨架，以及 **expand 成本闸门** 与 **性能边界**（§9）。

## 2. 公共约定与鉴权

### 2.1 传输

- Base：`http://127.0.0.1:{port}/v1`
- 有 body 的请求：`Content-Type: application/json`
- 字段命名：camelCase
- 时间：ISO-8601 UTC（`DateTimeOffset`）
- Guid：标准 UUID 字符串

### 2.2 响应信封

所有 `/v1` 成功与错误响应均使用：

```json
{
  "status": "ok",
  "message": null,
  "data": { }
}
```

| 字段 | 成功 | 错误 |
|---|---|---|
| `status` | 恒为 `"ok"` | 恒为 `"error"` |
| `message` | 无说明时 **`null`**；有说明时非空 string（如查询未知正词 notice） | 给人看的说明（非空） |
| `data` | 原业务体（单对象、分页列表、写回执等） | `{ "code": "<machine_code>", "details"?: { } }` |

不变量：

- **`status: "ok"` ⇔ HTTP 2xx**
- **`status: "error"` ⇔ HTTP 4xx / 5xx**
- 禁止 `200` + `status: "error"`；禁止非 2xx + `status: "ok"`
- 查询未知正词等软失败：HTTP `200` + `status: "ok"` + 非空 `message` + 空业务 `data`（见[查询语言细则 §5–§6](./2026-09-26-query-language.md)）

成功分页列表示例：

```json
{
  "status": "ok",
  "message": null,
  "data": { "items": [], "offset": 0, "limit": 50, "total": 123 }
}
```

错误示例：

```json
{
  "status": "error",
  "message": "Alias 'foo' not found.",
  "data": {
    "code": "tag_not_found",
    "details": { "alias": "foo" }
  }
}
```

`details` 可选，v1 允许但不强制；batch / 过滤 / 别名校验类错误建议带上。

实现：用统一 Result filter / middleware 收口；不依赖 ASP.NET 默认 ProblemDetails 形状。

### 2.3 鉴权

- 除 `GET /v1/health` 外：`Authorization: Bearer <token>`
- 缺失或错误 → `401`，`data.code: unauthorized`

### 2.4 分页

- Query：`offset`（默认 0）、`limit`（默认 50，上限 1024）
- 列表业务体在 `data` 内：`{ "items", "offset", "limit", "total" }`
- `GET /v1/query/preview` 的 `data` 可不含 `total`（允许省略以减负）

### 2.5 幂等

- `add` 已存在绑定 → 200，无变更
- `remove` 不存在绑定 → 200，无变更
- 创建时 alias / name / uri 冲突 → `409`
- 关系 batch：边已存在 → 整批 `409 relation_conflict`（集合校验，见 §3.5）

### 2.6 data_version

- 任意成功写与业务写同一事务递增 `data_version`
- 写响应推荐在 `data` 内带回 `"dataVersion": n`；读接口不强制
- `POST /v1/relations/batch` 整批成功只 +1 一次

### 2.7 标签集合排序

与数据模型一致：

1. `Seq` 升序（已设置的排在 null 之前）
2. 同 Seq / 皆 null → `CreatedAt` 升序
3. 再相同 → `Id` 升序

子标签 / related / neighbors 列表：用 **边上的** `TagRelation.Seq` / `CreatedAt`。  
**Seq 排序仅保证同一 `(fromTagId, kind)` 下有意义**；仅按 `toTagId` 列出时见 §3.5。  
全局标签列表、资源上的标签：用 **Tag** 自身字段。

### 2.8 资源集合排序

`GET /v1/resources`（无特殊排序参数时）、`GET /v1/query`、`GET /v1/query/preview` 的资源列表默认序：

1. `CreatedAt` 升序
2. 再相同 → `Id` 升序

## 3. 路由表

路由注册时：**字面量路径段优先于 `{id}` 参数**（例如 `/v1/tags/by-alias/...`、`/v1/resources/tags`、`/v1/resources/by-uri`、`/v1/relations/reorder`、`/v1/relations/batch` 不得被当成 Guid）。

下列「响应」描述的是信封中的 **`data`** 业务体（外层恒有 `status` / `message`）。

### 3.1 Health / Meta

| Method | Path | 说明 |
|---|---|---|
| `GET` | `/v1/health` | 存活；可无鉴权；`data`: `{ "health": "ok" }`（避免与信封 `status` 混淆） |
| `GET` | `/v1/meta` | 需鉴权；`data` 至少 `{ "dataVersion": n }` |

### 3.2 Tags

| Method | Path | 说明 |
|---|---|---|
| `GET` | `/v1/tags` | 列表；可选 `namespace`、`q`（前缀）；分页；默认排序 |
| `GET` | `/v1/tags/{id}` | 按 Guid；含 aliases、`nameInitials`（不含邻域） |
| `GET` | `/v1/tags/{id}/neighbors` | 一跳邻域；见下 |
| `GET` | `/v1/tags/by-alias/{alias}` | 双轨解析；alias URL 编码 |
| `POST` | `/v1/tags` | 创建；见下 |
| `PATCH` | `/v1/tags/{id}` | 改 `name` / `namespace` / `seq` |
| `DELETE` | `/v1/tags/{id}` | 级联删别名、绑定、相关边 |
| `POST` | `/v1/tags/{id}/aliases` | body：`{ "alias": "..." }` |
| `DELETE` | `/v1/tags/{id}/aliases/{alias}` | 禁止删到零个别名（至少保留一个） |

`POST /v1/tags` body：

```json
{
  "name": "工作",
  "namespace": null,
  "seq": null,
  "aliases": null
}
```

- 未提供 `aliases`（或空）→ 自动插入默认别名 = `name`（默认别名也须通过别名字符集校验；若 `name` 本身违规 → `422 validation_failed`）
- `nameInitials` **只读**：服务端由 `name` 生成；POST/PATCH 不可写；改 `name` 时重算
- 显式 `aliases` / `POST …/aliases`：须符合[数据模型别名字符集](./2026-09-23-data-model.md)；违规 → `422 validation_failed`，`details` 含原因；服务端日志写清 `alias_rejected_*`

`GET /v1/tags?q=` 与 `GET /v1/tags/suggest`：前缀匹配 **`AliasNormalized` 或 `NameInitials`**（OR）。  
若因简拼命中：`suggest` 的 `alias` 字段返回该 Tag 的**默认展示别名**（优先与 `name` 相同的别名，否则按别名创建序第一条）。

无 `q`：`GET /v1/tags` = 普通分页列表。空 `q` 或仅空白：`suggest` → `400 bad_request`；`GET /v1/tags?q=` 同 suggest（空白不当检索）。

#### `GET /v1/tags/{id}/neighbors`

图浏览入口（与边表 `/relations` 分工：本接口带对端 Tag 摘要）。

| Query | 说明 |
|---|---|
| `direction` | `out` \| `in` \| `both`；默认 **`both`**（相对路径上的 `{id}`） |
| `kind` | 可选；单个或逗号分隔 `child,related`；缺省 = 两种都返回 |
| `offset` / `limit` | 同 §2.4 |

- 标签不存在 → `404 not_found`
- `data`：分页列表；`items` 每项含 `kind` + `direction` + 边字段 + 对端摘要
- 排序：在同一 `(fromTagId, kind)` 语义可比较时用边 Seq 规则；否则 `CreatedAt ASC, Id ASC`
- **不对端再嵌套邻域**；摘要 **不含** `aliases`

### 3.3 Resources

| Method | Path | 说明 |
|---|---|---|
| `GET` | `/v1/resources` | 可选 `kind`、`uri`（**精确**）；分页；默认序见 §2.8；不提供 URI 模糊 |
| `GET` | `/v1/resources/{id}` | 按 Guid；可含当前 tags |
| `GET` | `/v1/resources/by-uri` | query：`uri=`（避免路径编码）；可含 tags |
| `POST` | `/v1/resources` | `uri`, `kind`, `displayName?`；服务端规范化 URI |
| `PATCH` | `/v1/resources/{id}` | 仅 `displayName` / `kind`；**v1 禁止改 uri** |
| `DELETE` | `/v1/resources/{id}` | 删资源及绑定 |

### 3.4 打标 action

| Method | Path | 说明 |
|---|---|---|
| `POST` | `/v1/resources/tags` | 批量 add / remove |
| `GET` | `/v1/resources/tags` | query：`resourceId=` **或** `uri=`；该资源标签列表 |

`POST /v1/resources/tags` body：

```json
{
  "resourceId": null,
  "uri": "file:///C:/a.txt",
  "kind": "file",
  "displayName": null,
  "add": ["工作", { "id": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee" }],
  "remove": ["归档"],
  "createMissing": false
}
```

规则：

- `resourceId` 与 `uri` 至少其一；都有时以 `resourceId` 为准，且须与库中 uri 一致，否则 `409 resource_id_uri_mismatch`
- 资源不存在且提供了 `uri` → **隐式创建**。`kind`：显式传入，或由 scheme 推断（`http`/`https` → `url`）；无法推断时 → `422`（调用方须传 `kind`）
- `add` / `remove` 元素：字符串 = alias，或对象 `{ "id": "<guid>" }`
- **`add` 与 `remove` 元素总数上限 100**；超出 → `422 batch_limit_exceeded`
- `createMissing: true`：仅对 `add` 中未知 **alias 字符串** 自动建 Tag（默认别名 = 名，并生成 `nameInitials`）；别名须通过字符集校验，否则 `422 validation_failed`；未知 Guid → `404 tag_not_found`
- 默认 `createMissing: false`：未知别名 → `404 tag_not_found`

成功时 `data` 示例：

```json
{
  "resource": { },
  "createdTags": [],
  "added": ["..."],
  "removed": ["..."],
  "dataVersion": 42
}
```

`resource` 含当前 tags；`createdTags` 为因 `createMissing` 新建的 Tag（可空数组）；`added` / `removed` 为本次实际变更的 tagId 列表。

### 3.5 Relations

| Method | Path | 说明 |
|---|---|---|
| `GET` | `/v1/relations` | **必须**提供 `fromTagId` **或** `toTagId`（可同时有）；可选 `kind`；分页 |
| `GET` | `/v1/relations/{id}` | |
| `POST` | `/v1/relations` | `fromTagId`, `toTagId`, `kind`, `seq?` |
| `POST` | `/v1/relations/batch` | 批量**仅创建**；见下 |
| `PATCH` | `/v1/relations/{id}` | 仅 `seq`；v1 不改端点或 kind（删再建） |
| `DELETE` | `/v1/relations/{id}` | |
| `POST` | `/v1/relations/reorder` | 批量重排 |

`GET /v1/relations`：

- 缺少 `fromTagId` 与 `toTagId` → `400 bad_request`（`code` 可用 `relations_filter_required`，或归入 `bad_request` + message）
- 提供 `fromTagId`（建议同时有 `kind`）→ 同 `(From, Kind)` 按边 Seq 规则排序
- **仅** `toTagId` → 排序固定为 `CreatedAt ASC, Id ASC`（跨 From 的 Seq 不可比）
- 职责：原始边 CRUD / 排查；图浏览用 `neighbors`

`POST /v1/relations`：成环 → `409 relation_cycle`；child 单父冲突或边已存在 → `409 relation_conflict`；自环 / 非法 kind → `422`  
`related` **不**自动建反向边；需要双向则显式写两条（可用 batch）。

`POST /v1/relations/batch` body：

```json
{
  "items": [
    { "fromTagId": "...", "toTagId": "...", "kind": "related", "seq": null },
    { "fromTagId": "...", "toTagId": "...", "kind": "child", "seq": 0 }
  ]
}
```

规则：

- **仅创建**；删除仍用单条 `DELETE`；重排仍用 `reorder`
- `items` 长度 1..**100**；空或超限 → `422 batch_limit_exceeded`
- 允许同一请求混 `child` / `related`
- **集合语义**：在「旧图 ∪ 本批全部新边」上校验自环 / 非法 kind / 唯一冲突 / child 单父 / child 成环；全部合法才写入；单事务；`data_version` +1
- 失败 → 对应 `409` / `422`；`data.details` 含 **`index`**（`items` 下标）及该边的 `fromTagId` / `toTagId` / `kind`（实现按数组序报告第一个违规项）
- 成功：`data` 为创建的 relations 数组形态，或 `{ "items": [...], "dataVersion": n }`（实现选定一种并在 OpenAPI/示例中固定；推荐带 `dataVersion` 的对象）

`POST /v1/relations/reorder` body：

```json
{
  "fromTagId": "...",
  "kind": "child",
  "orderedToTagIds": ["...", "..."]
}
```

- 必须恰好覆盖该 `(fromTagId, kind)` 下全部现有边的 `toTagId`；集合不一致 → `422 validation_failed`
- 按数组下标写入 `Seq`（0..n-1）；单事务
- 成功：`data` 含重排后的 relations 与 `dataVersion`

### 3.6 Query（骨架）

| Method | Path | 说明 |
|---|---|---|
| `GET` | `/v1/tags/suggest?q=&limit=` | 别名或 `nameInitials` 前缀建议；`q` 必填且非空白 |
| `GET` | `/v1/query/preview?q=&limit=` | 少量命中 |
| `GET` | `/v1/query?q=&offset=&limit=` | 完整分页 |

- `expand=child`（语法见 [查询语言细则](./2026-09-26-query-language.md)）；**v1 仅支持沿 `Kind=child` 展开**；`related` **不**参与查询集合展开（浏览走 `neighbors`）
- 可选下调成本：`maxDepth`（默认 **8**，允许 **0…serverMax**）、`expandedTagLimit`（默认 **512**，允许 **1…serverMax**）；不得超过服务端上限（与默认相同，除非实现另行配置且文档化）
- **深度**：只收集 `depth ≤ maxDepth`（截断，**不**因此 422）
- **标签数**：正负展开合并去重后触顶，或请求参数 `>` serverMax → `422 expansion_limit_exceeded`
- 参数非整数 / 负数 / `expandedTagLimit=0` 等形状非法 → `400 bad_request`
- 闸门常量须在代码集中定义并与文档同源（见[查询语言细则 §3.1](./2026-09-26-query-language.md)）
- 未知**正词**：`200` + `status: "ok"` + 非空 `message` + 空列表（不用 4xx）
- 未知**负词**：忽略该负词；通常仅日志
- 资源序：§2.8
- 查询缓存键必须包含 `expand`、`maxDepth`、`expandedTagLimit`（及 `op` / 规范化查询串 / 分页）；未展开占位与规范化算法见 [查询语言细则 §4](./2026-09-26-query-language.md)

## 4. JSON 形状

以下为信封内 **`data`**（或 `data` 内嵌套实体）的形状；外层 `status` / `message` 见 §2.2。

### 4.1 Tag

```json
{
  "id": "...",
  "name": "工作",
  "namespace": null,
  "seq": 1,
  "nameInitials": "gz",
  "aliases": ["工作", "work"],
  "createdAt": "2026-09-26T12:00:00Z",
  "updatedAt": "2026-09-26T12:00:00Z",
  "revision": 1
}
```

### 4.2 Resource

```json
{
  "id": "...",
  "uri": "file:///C:/a.txt",
  "kind": "file",
  "displayName": null,
  "createdAt": "...",
  "updatedAt": "...",
  "revision": 1,
  "tags": []
}
```

列表接口可省略 `tags`；详情与打标响应建议带上。

### 4.3 TagRelation

```json
{
  "id": "...",
  "fromTagId": "...",
  "toTagId": "...",
  "kind": "child",
  "seq": 0,
  "createdAt": "...",
  "updatedAt": "...",
  "revision": 1
}
```

### 4.4 Neighbor item

```json
{
  "id": "...",
  "fromTagId": "...",
  "toTagId": "...",
  "kind": "child",
  "seq": 0,
  "direction": "out",
  "createdAt": "...",
  "updatedAt": "...",
  "revision": 1,
  "tag": {
    "id": "...",
    "name": "待读",
    "namespace": null,
    "nameInitials": "dd"
  }
}
```

- `direction`：相对路径 `{id}` 的 `out` 或 `in`
- `tag`：对端摘要；**无** `aliases` / `seq` / 时间戳（需要完整 Tag 再 `GET /tags/{id}`）

### 4.5 suggest / query item

```json
// suggest item
{ "tagId": "...", "alias": "工作", "name": "工作", "namespace": null, "nameInitials": "gz" }

// preview / query item
{ "id": "...", "uri": "...", "kind": "file", "displayName": null }
```

查询未知正词时完整响应示例：

```json
{
  "status": "ok",
  "message": "Unknown positive term 'typo'; returning empty result.",
  "data": { "items": [], "offset": 0, "limit": 50, "total": 0 }
}
```

### 4.6 错误 `data`

```json
{
  "code": "tag_not_found",
  "details": { "alias": "foo" }
}
```

与顶层 `status: "error"`、`message` 组成完整错误响应（见 §2.2）。

## 5. 错误码

| HTTP | code（位于 `data.code`） | 何时 |
|---|---|---|
| 401 | `unauthorized` | 缺/错 token |
| 400 | `bad_request` | JSON 无效、缺必填、`resourceId`/`uri` 都空、suggest/tags 空 `q`、`relations` 缺端点过滤、查询结构非法、expand/闸门参数形状非法等 |
| 400 | `relations_filter_required` | `GET /v1/relations` 未提供 `fromTagId` 且未提供 `toTagId`（可与 `bad_request` 二选一实现，契约承认此码） |
| 404 | `not_found` | 路径上的实体 id 不存在 |
| 404 | `tag_not_found` | 别名/Guid 无法解析（含 `createMissing=false`） |
| 404 | `resource_not_found` | 仅有 resourceId 且不存在；或 by-uri 未命中 |
| 409 | `alias_conflict` | 别名全局唯一冲突 |
| 409 | `name_conflict` | 同 namespace 下主名冲突 |
| 409 | `uri_conflict` | 资源 URI 冲突 |
| 409 | `relation_conflict` | 边已存在 / child 单父冲突 |
| 409 | `relation_cycle` | child 成环 |
| 409 | `resource_id_uri_mismatch` | 同时传 id 与 uri 且不一致 |
| 422 | `validation_failed` | kind 非法、自环、reorder 集合不完整、删光最后一个 alias、无法推断 kind、**别名字符集违规**等 |
| 422 | `batch_limit_exceeded` | 关系 batch 或打标 `add`+`remove` 超过上限 |
| 422 | `expansion_limit_exceeded` | `expandedTagLimit` 触顶，或 `maxDepth`/`expandedTagLimit` 请求值大于服务端上限（**不含**深度截断） |
| 500 | `internal_error` | 未处理异常 |

枚举：

- Resource `kind`：`file` | `folder` | `url`
- Relation `kind`：`child` | `related`（其它 → `422`）

### 5.1 删除标签级联

删除 Tag → 级联删除其 aliases、所有 `ResourceTag`、所有以之为 `From` 或 `To` 的 `TagRelation`；`data_version` +1。

## 6. nameInitials（简拼）

| 项 | 约定 |
|---|---|
| 存储 | 仅 `Tag.NameInitials`（由主名生成；不按 Alias 存简拼） |
| 生成时机 | 创建 Tag、PATCH 改 `name`、`createMissing` 建标时 |
| 算法 | 汉字 → 拼音首字母小写；ASCII 字母数字 → 小写保留；其余跳过。例：`工作笔记` → `gzbj`，`API设计` → `apisj` |
| 多音字 | v1 用拼音库默认读音，不求全覆盖 |
| API | 响应只读字段；不可写入 |
| 检索 | `suggest` 与 `GET /v1/tags?q=` 对 `NameInitials` 做前缀匹配 |

字段与索引细节见[数据模型](./2026-09-23-data-model.md)。

## 9. 性能边界（契约硬约束）

不规定毫秒 SLA。下列访问模式 **禁止或强制**，以保证走数据模型索引热路径：

| 约束 | 说明 |
|---|---|
| 前缀检索 | `suggest` / `GET /v1/tags?q=` **仅** `AliasNormalized` / `NameInitials` 前缀（`LIKE 'prefix%'`）；**禁止**前后缀 / substring（`%x%`） |
| 空查询 | `suggest` 与带空白 `q` 的 tags 检索 → `400`；无 `q` 的 tags = 普通列表 |
| 关系列表 | `GET /v1/relations` **必须** `fromTagId` 或 `toTagId`；禁止无过滤全图表 |
| 资源 URI | `GET /v1/resources` 的 `uri` **仅精确匹配**；无模糊 |
| 分页 | 列表接口必须分页；`limit` 默认 50、上限 1024 |
| 打标批量 | 单次 `add`+`remove` 元素总数 ≤ 100 |
| 关系 batch | 单次 `items` ≤ 100；集合校验后一次提交 |
| 查询展开 | 仅 `expand=child`；默认 `maxDepth=8`、`expandedTagLimit=512`；可下调不可超服务端上限；深度截断、标签数触顶 422 |
| 缓存键 | `v{data_version}:{op}:{normalized_query}:{expand}:{maxDepth}:{expandedTagLimit}:{limit}:{offset}`；未展开时 `expand=none`、`maxDepth=0`、`expandedTagLimit=0`（见 [查询语言细则](./2026-09-26-query-language.md)） |
| 响应信封 | 全 `/v1` 使用 `{ status, message, data }`；见 §2.2 |
