# #11 CLI `el` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付薄客户端 `el.exe`（AssemblyName `el`）与共享 `EverythingLabeled.Client` / `PathUri`，只走 Service HTTP + Bearer，覆盖 CLI 规格命令面。

**Architecture:** PathUri 只做字符串 URI 规范化（Service 薄封装调用）。Client 提供 `ElConfig`、`ElResult`、`IElApi`/`HttpElApi`、`FileTarget`（存在性 / symlink / `kind`）。CLI 用 System.CommandLine 解析、人类/`--json` 输出、退出码、TTY `untag` 确认、离线 `completion powershell`。闸门与用法校验在 CLI；确认策略不进 Client。

**Tech Stack:** .NET 8 classlib + exe；`System.CommandLine` **2.0.12**；`System.Text.Json`；xunit。不引入 Spectre、不建 Contracts 工程、不用 `IHttpClientFactory`。

**Spec:** [plans/2026-09-26-cli.md](./2026-09-26-cli.md)。HTTP：[plans/2026-09-26-http-api.md](./2026-09-26-http-api.md)。URI：[数据模型 §2](./2026-09-23-data-model.md)。MCP 对 Client 的预期：[plans/2026-09-27-mcp.md](./2026-09-27-mcp.md) §2.2。审核：[confirmed/2026-10-06-cli-impl-review.md](./confirmed/2026-10-06-cli-impl-review.md)（Q1–Q21 均选推荐 A）。Explorer 共用 PathUri 留给 #14，本计划只把库放进 sln。

## Global Constraints

- TFM `net8.0`；`<Nullable>enable</Nullable>`；`<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`；`InternalsVisibleTo` 对应测试程序集。
- 只走 HTTP + Bearer；`Accept: application/json`。`HealthAsync` **不**带 `Authorization`。
- 覆盖优先级（均不写回）：CLI flag `--config` / `--base-url` / `--token` > env `EL_CONFIG` / `EL_BASE_URL` / `EL_TOKEN` > config 文件。未知 JSON 键忽略。`baseUrl`/`token` 必填非空。`confirmUntag` 缺省 `true`。无文件但 flag/env 已凑齐 url+token → 成功，`confirmUntag=true`。缺必填 → `config_missing`。
- HTTP 整请求超时 **30s**；超时、无法连接、取消 → `connection_failed`。v1 无 `--timeout`。
- 退出码：0 成功（含幂等 200、查询 notice）；1 本地用法/校验/`path_not_found`/untag 取消；2 `config_missing` / `connection_failed`；3 HTTP 4xx；4 HTTP 5xx。
- `--version` / `-h` / `--help` / `completion powershell` 打印脚本：不读 config、不连服务。
- `--json` 成功 stdout **仅** API `data`（紧凑 camelCase）；notice/分页在 stderr。错误 `--json`：stderr `{"error":{"code":"...","message":"..."}}`。
- 仅 `tag` 传 `kind`；不传 `displayName`/`resourceId`。`createMissing` 仅 `--create`/`-c`。`untag` 永不 `createMissing: true`。
- `suggest` HTTP 查询参数是 **`q=`**（不是 `prefix=`）；CLI 位置参数原样提交。
- `preview`/`suggest` 省略 `--limit` 时 **必须**传 `limit=10`。`query` 省略传 `50`。`offset` 仅 query，默认 0。
- 未带 `--expand` 却写了 `--max-depth` 或 `--expanded-tag-limit` → 本地 `bad_request`。`--expand` 仅允许 `child`。
- 数字非法（非整数、负、`limit=0` 或 `>1024`）、空 alias（trim 后）、空 `q`/`prefix`、alias 数 0 或 >100、多位置参数 → 本地 `bad_request`，不发请求。
- `GetTags` 翻页 limit=1024 直到取完。
- 人类输出钉死（Q8–Q10）：见 Task 6–7。help/`--version` **英文**。启动 stdout/stderr UTF-8。
- `IElApi` 签名不得改名/增方法（Q12）。DTO 仅 Client 自有 record。
- 不做：标签/关系 CRUD、CLI `health`、安装到 LocalAppData、写 config、TUI、多 target、递归打标、cmd/bash 补全、Contracts 工程、Client.Tests 引用 Service。
- commit subject：仓库递增 `#序号`（`git log -1 --format=%s` +1），**不要** backlog `#11`；不用 conventional commits。PowerShell 下用 here-string 传 `-m`。

```csharp
namespace EverythingLabeled.PathUri;

public readonly record struct CanonicalTarget(string Uri, string Scheme);

public static class PathUriCanonicalizer
{
    public static bool TryCanonicalize(string target, out CanonicalTarget result);

    public static bool IsKindCompatible(string scheme, string kind) => (scheme, kind) switch
    {
        ("http", "url") => true,
        ("https", "url") => true,
        ("file", "file") => true,
        ("file", "folder") => true,
        _ => false,
    };
}
```

`TryCanonicalize` **必须**复现当前 `UriNormalizer` 的字符串行为（可把现实现几乎原样搬来，去掉 `ServiceResult` / kindHint）：

- trim；空 → false
- `Uri.TryCreate(Absolute)` 或 `new Uri(Path.GetFullPath(raw))` 且 `IsFile`
- `http`/`https`：scheme/host 小写；默认端口省略；去 fragment；保留 query（与现 `NormalizeHttp` 相同，用 `GetComponents(HttpRequestUrl, UriEscaped)`）
- `file`：UNC `file://{host-lower}{path}` 非根去尾 `/`；盘符路径盘符大写、`/`、根保留尾 `/`（与现 `NormalizeFile` 相同）
- `Scheme` 为规范化后的 `http` / `https` / `file`（小写）
- 其它 scheme → false

`UriNormalizer.Normalize`：`TryCanonicalize` 失败 → 现有 `validation_failed` 文案；kindHint 空则 http(s)→`url` 否则 `file`；再 `IsKindCompatible`，失败带 `details.reason=kind_uri_mismatch`。

### Task 6: `tag` / `untag` / `tags` + 确认 + 人类/`--json`

**Files:**

- Modify: `ElApp.cs`（子命令）
- Create: `HumanFormatter.cs`、`Cli/CommandSupport.cs`（解析 target、本地校验）
- Create: `tests/.../TagCommandsTests.cs`

**行为：**

1. 规范化 target：`http(s)`/`file://` 或路径 → PathUri。失败 → `bad_request`。
2. `tag`：file → `FileTarget.ResolveKindForTag`；http(s) → kind `url`。别名 1–100，逐个 trim，空 → `bad_request`。`--create`/`-c`。调用 `TagAsync`。
3. `untag`：不检查存在、不传 kind。需确认当 `ConfirmUntag && !--yes`：TTY 则 stderr `Remove alias(es) [a, b] from <uri>? [y/N]`，stdin 仅 `y`/`Y` 继续；其它/空 → exit 1 不调 API。非 TTY → `bad_request` 提示加 `--yes`。`--yes`/`-y` 跳过。`LoadConfig` 取 `ConfirmUntag`（有注入 Api 时仍要 config 才能知道开关——测试注入 `LoadConfig` 返回固定 `ElConfig` + 假 Api）。
4. `tags`：`GetTagsAsync`，每行一个 alias（Q9）。

人类 tag/untag（Q8）：用请求 alias 对照 `ResourceTags`+`CreatedTags` 的 Aliases 找到 TagId；若该 id 在 Added/Removed 则按用户顺序列入。`added: a, b` / `removed: a, b`。CreatedTags 非空：`created: n1, n2`（Name，逗号+空格）。Added/Removed 空：一行 `unchanged`（不打 created 除非有 CreatedTags——幂等无新建则 unchanged）。

`--json`：stdout 序列化 **API data**。假 Api 可返回 `TagApplyData`；json 测用真形状：至少含 `added`/`removed`/`createdTags`/`dataVersion`。若假对象与 HTTP 不完全同形，json 成功路径应用 `HttpElApi` 测过的 data 或 CLI 把 `TagApplyData` 序列化 Web 默认（实现选一种并在测试钉字符串）。**推荐：** CLI `--json` 对 tag/untag/tags/query 把 `IElApi` 返回的 DTO 用 Web JSON 写出（与信封 data 字段同名：tag 输出需匹配 API——`resource`/`createdTags`/`added`/`removed`/`dataVersion`）。因此 `TagApplyData` 不够；改为：

```csharp
public sealed record TagApplyData(
    ResourceDetail Resource,
    IReadOnlyList<CreatedTag> CreatedTags,
    IReadOnlyList<Guid> Added,
    IReadOnlyList<Guid> Removed,
    int DataVersion);
public sealed record ResourceDetail(Guid Id, string Uri, string Kind, string? DisplayName, IReadOnlyList<TagInfo> Tags);
```
