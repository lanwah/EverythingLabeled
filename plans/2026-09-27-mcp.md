## 1. 设计摘要

- MCP 为本机**薄客户端**：与 CLI 同级；只经 Service HTTP（Bearer），不直连 SQLite。
- v1 交付：**stdio transport**（Cursor / Claude Desktop 等起子进程）；**仅 Tools**（无 Resources / Prompts）。
- 工具名统一 `el_` 前缀：`el_tag` / `el_untag` / `el_tags` / `el_query` / `el_preview` / `el_suggest` / `el_health`。
- **不做**：标签/关系 CRUD、在 MCP 内启停服务或写 config、`el_meta`。
- 工程：`Client` → `Mcp.Tools` → `Mcp` host；Tools 依赖 `IElApi`，v1 仅 `HttpElApi`；预留日后 Service 内 HTTP MCP。
- 配置与 CLI **同一 SSOT**（AppData + flag + `EL_*`）。
- 成功返回 **有意不同于** CLI `--json`：统一 `{ "data", "message" }`（见 §6）。

## 2. 定位与架构

### 2.1 职责

| 能力 | v1 |
|---|---|
| stdio MCP host | ✓ |
| Tools（CLI 同级 + `el_health`） | ✓ |
| 读 AppData config / flag / `EL_*` | ✓ |
| `--help` / `--version`（离线） | ✓ |
| HTTP MCP / `MapMcp` | ✗（预留，见 §7） |
| InProc `IElApi` | ✗（预留） |
| Resources / Prompts | ✗ |
| 标签 / 关系 CRUD tools | ✗ |
| `el_meta` | ✗ |

### 2.2 进程与依赖

```text
[Cursor / Claude Desktop / …]
        │ stdio (MCP)
        ▼
EverythingLabeled.Mcp          ← transport only；stdout 仅协议
        │
        ▼
EverythingLabeled.Mcp.Tools    ← [McpServerTool*]；无 SQLite 依赖
        │
        ▼
IElApi  （EverythingLabeled.Client）
        │
        └─ HttpElApi ── HTTP Bearer ──► EverythingLabeled.Service /v1
```

| 项目 | 职责 |
|---|---|
| `EverythingLabeled.Client` | config 加载、`IElApi`、`HttpElApi`、路径↔URI / `kind` 推断；覆盖**已确认客户端**（CLI / MCP / Explorer / 扩展）所需 `/v1` 表面，可超集于 MCP Tools |
| `EverythingLabeled.Mcp.Tools` | 工具方法；Description **英文**；本地策略（untag confirm 等） |
| `EverythingLabeled.Mcp` | stdio host；DI；**必须**支持 `--config` / `--base-url` / `--token` |

不变量：

- Tools **不**引用 ASP.NET / SQLite；**不**直连库。
- 新路径/URI 规则只进 `Client`；禁止 MCP 私有复制。
- CLI 可逐步迁到同一 `Client`；**不要求**与 MCP v1 同步改完。
- v1 **不**对 MCP tool 调用做并发限流（不绑定 Explorer 的 `maxConcurrency`）。

### 2.3 技术栈与 stdio 约束

- .NET + 官方 `ModelContextProtocol`（stdio）。
- 工具用 `[McpServerToolType]` / `[McpServerTool]` + `[Description]`（参数亦须 Description；**英文**）。
- **禁止**往 stdout 写日志/诊断/人类文本；协议模式 stdout **仅** MCP 帧。日志与诊断走 **stderr**（或 SDK 等价通道）。
- `--help` / `--version`：不读 config、不连服务，可离线 exit 0；**仅**在以 flag 启动且未进入 MCP 会话时打印到 stdout/约定流。进入 stdio MCP 会话后不得再污染 stdout。

## 3. 工具表与参数

命名：`el_` + snake_case。语义对齐 [CLI 规格](./2026-09-26-cli.md) §3–§5（`el_health` 除外）。  
`el_query` Description 应建议 Agent：**大结果集先 `el_preview`**；默认 limit 仍与 CLI 一致（不独降）。

| Tool | CLI / HTTP | 主要参数 | 默认 |
|---|---|---|---|
| `el_tag` | `el tag` → `POST /v1/resources/tags` add | `target`, `aliases` (`string[]`), `create_missing?` | `create_missing=false` |
| `el_untag` | `el untag` → remove | `target`, `aliases` (`string[]`), `confirm?` | 见 §4 |
| `el_tags` | `el tags` → `GET /v1/resources/tags` | `target` | — |
| `el_query` | `el query` → `GET /v1/query` | `q`, `expand?`, `max_depth?`, `expanded_tag_limit?`, `limit?`, `offset?` | 不 expand；limit **50**；offset **0** |
| `el_preview` | `el preview` → `GET /v1/query/preview` | 同 query（无 `offset`） | limit **10** |
| `el_suggest` | `el suggest` → `GET /v1/tags/suggest` | `prefix`, `limit?` | limit **10** |
| `el_health` | — → `GET /v1/health` | （无） | 见 §3.1 |

共用规则：

- `target`：本机路径或 URI；规范化与 `kind` 在 **Client**，与 CLI §3–§4 一致。
  - **相对路径**相对 **MCP 进程 cwd**（由宿主决定；不确定时用绝对路径或 URI，并可在 mcp.json 设 `cwd`）。
  - `el_tag`：本机路径 / `file://` **必须存在**（含 symlink 目标；断链 → `path_not_found`）；`http(s)` 不检查本地。
  - `el_untag` / `el_tags`：**不**检查本地存在性。
- `aliases`：JSON **`string[]` only**（不接受逗号/空格拼接的单字符串）；至少 1 个、最多 **100**；元素 trim 后空或超限 → 本地 `bad_request`，不发请求。
- 单 `target`；不传 `resourceId` / `displayName`；仅 `el_tag` 传推断的 `kind`。
- `create_missing`：默认 `false`；为 true 时 API `createMissing: true`。
- `expand`：仅允许 `"child"`；未传 `expand` 却传了闸门参数 → 本地 `bad_request`。
- 查询串 `q` / `prefix`：原样提交；trim 后空 → 本地 `bad_request`。

不做：`completion`、打开资源、多 target、目录递归批量打标、`el_meta`。

### 3.1 `el_health`

- 调用 `GET /v1/health`（API **免鉴权**）。
- **不要求** token：只要能解析出 `baseUrl`（flag / env / config）即可；缺 `baseUrl` → `config_missing`。
- 完整 config 中的 `token` 可忽略；请求可不带 `Authorization`。
- 用于探活；验 token 靠其它业务 tool 的 `unauthorized`。
- 成功时 `data` 为 API 的 health 业务体（如 `{ "health": "ok" }`），外层仍走 §6.1。

## 4. `untag` 确认

CLI 有 TTY 确认；MCP **无交互**，用参数等价于 `--yes`。

| 条件 | 行为 |
|---|---|
| config `confirmUntag == false` | 直接 `remove` |
| `confirmUntag != false`（缺省 **true**）且未传 `confirm=true` | **不发请求**；`confirmation_required`，提示再次调用并设 `confirm=true` |
| 同上且 `confirm=true` | 直接 `remove` |

- Tool description 标明 destructive，并写清上表。
- `confirmUntag: false` 时多余的 `confirm=true` 无害。
- `el_untag` 永不 `createMissing: true`。

## 5. 配置与客户端接入

### 5.1 配置

默认路径：`%AppData%/EverythingLabeled/config.json`。

```json
{
  "baseUrl": "http://127.0.0.1:5123",
  "token": "<local-secret>",
  "confirmUntag": true
}
```

- 业务 tool（除 `el_health`）：`baseUrl`、`token` 必填，非空。
- `confirmUntag`：可选；缺省键或省略 = `true`。
- 未知键忽略。
- 每个需鉴权请求：`Authorization: Bearer <token>`，`Accept: application/json`。
- 覆盖优先级（**均不写回**）：
  1. host flag（**v1 必须支持**）：`--config` / `--base-url` / `--token`
  2. 环境变量：`EL_CONFIG` / `EL_BASE_URL` / `EL_TOKEN`
  3. config.json
- 整请求超时默认 **30s**；超时 → `connection_failed`。
- MCP **不**负责安装服务、写首次 token（→ backlog 配置与安装）。

### 5.2 Cursor / 同类示意

```json
{
  "mcpServers": {
    "everything-labeled": {
      "command": "path/to/EverythingLabeled.Mcp.exe",
      "args": [],
      "cwd": "<optional-workspace-root>"
    }
  }
}
```

- 通常只配 `command`；token 走 AppData。
- `cwd` **可选**：影响相对路径解析；不强制。
- 需要覆盖时用 `env`（`EL_BASE_URL` / `EL_TOKEN` / `EL_CONFIG`）。
- 服务未启动 → 业务 tool 返回 `connection_failed`；可用 `el_health` 探活。MCP **不**拉起 daemon。

## 6. 返回与错误

### 6.1 成功

统一形状（**有意不同于** CLI `--json` 的裸 `data`；因 Agent 无可靠 stderr notice 通道）：

```json
{
  "data": { },
  "message": null
}
```

- `data`：API 信封中的业务 `data`。
- `message`：API 信封的 `message`；无 notice 时为 **`null`**；非空时**不得丢弃**。
- 工具结果 **`isError: false`**（含带 notice 的软成功）。

### 6.2 失败

```json
{
  "error": {
    "code": "bad_request",
    "message": "…"
  }
}
```

- 工具结果 **`isError: true`**。

本地 `code`：

| code | 场景 |
|---|---|
| `config_missing` | 配置文件或必填字段缺失（`el_health` 仅缺 `baseUrl` 时亦然） |
| `path_not_found` | `el_tag` 目标路径 / `file://` 本地不存在或断链 |
| `confirmation_required` | `el_untag` 需要 `confirm=true` 而未提供 |
| `bad_request` | 其它用法/校验错误 |
| `connection_failed` | 无法连接 `baseUrl` 或请求超时 |

HTTP 业务错误：透传 API `data.code` + `message`（如 `tag_not_found`、`unauthorized`）。  
stdio 对 Agent **无** CLI 式 exit code 语义。

## 7. 预留：HTTP MCP（非 v1）

目标：日后在 Service 进程内 `MapMcp`，Tools **零改签名**。

| 步骤 | 内容 |
|---|---|
| 1 | Service 引用 `EverythingLabeled.Mcp.Tools` |
| 2 | 注册 `InProcElApi`（或同等应用层门面）实现 `IElApi` |
| 3 | `MapMcp`；鉴权与回环策略与现有 HTTP API 对齐 |
| 4 | 仅换 DI 与 transport；不改工具参数与 Description 契约 |

v1 **不**实现本小节；实现时另开规格修订。

## 8. v1 非目标

- HTTP MCP / `MapMcp` / `InProcElApi`
- MCP Resources / Prompts
- 标签 / 关系管理 tools、`el_meta`
- 多 target、目录递归批量打标、打开/启动资源
- 在 MCP 内启停 Service、安装、写 config
- TTY 交互确认（仅 `confirm` 参数）
- MCP 专用调用限流 / 绑定 `maxConcurrency`
- 强制与 CLI 同步完成 Client 迁移（禁止双份路径规则即可）
- 将 CLI `--json` 成功形状改为与 MCP 相同

## 9. 自检清单（实现时）

- [ ] Tools 只经 `IElApi`；stdio host 注入 `HttpElApi`
- [ ] flag > env > config；不写回；`--help` / `--version` 离线且不污染 MCP stdout
- [ ] stdout 仅 MCP 协议；日志走 stderr
- [ ] 工具名 `el_*`；Description 英文；`aliases` 仅为 `string[]`
- [ ] 默认与 CLI 一致（`create_missing`、expand、limit/offset）；Description 引导先 preview
- [ ] `el_untag`：`confirmUntag` + `confirm` → `confirmation_required`
- [ ] `el_health`：免 token；只需 `baseUrl`
- [ ] 相对路径 = 进程 cwd；路径 / URI / `kind` 与 CLI **同库**
- [ ] 成功 `{ data, message }`；失败 `{ error }` + `isError: true`；notice 不丢
- [ ] Cursor 配 `command`（可选 `cwd`）即可；`Mcp.Tools` 无 ASP.NET / SQLite 引用
