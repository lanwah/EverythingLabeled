## 1. 设计摘要

- `el` 为本机**薄客户端**：只调 Service HTTP，不直连 SQLite。
- v1 命令面（动词优先、扁平子命令）：`tag` / `untag` / `tags` / `query` / `preview` / `suggest` / `completion`。
- **不做**：标签 CRUD、关系管理、启停服务、装卸载、TUI、打开资源、目录递归批量打标、多 target 单次调用。
- 本机路径自动规范为 `file://` URI；读 `%AppData%/EverythingLabeled/config.json`（可被 flag / 环境变量覆盖，**不写回**）。
- 默认人类可读输出；`--json` 成功时 stdout **仅** API `data`。默认**不** `expand`；打标默认**不**自动建标（`--create` / `-c` 才建）。
- `untag` 默认二次确认（`confirmUntag`，可用 `--yes` / `-y` 跳过）。

## 2. 定位与连接

### 2.1 职责

| 能力 | v1 |
|---|---|
| 打标 / 去标 | ✓ |
| 查看资源标签 | ✓ |
| 查询 / 预览 | ✓ |
| 标签建议 | ✓ |
| PowerShell 补全脚本 | ✓ |
| 标签 / 关系 CRUD | ✗（直接调 API 或后续 UI） |

### 2.2 配置

默认路径：`%AppData%/EverythingLabeled/config.json`。

```json
{
  "baseUrl": "http://127.0.0.1:5123",
  "token": "<local-secret>",
  "confirmUntag": true
}
```

- `baseUrl`、`token`：必填，非空字符串。
- `confirmUntag`：可选；**缺省键或省略 = `true`**（CLI 读 AppData；浏览器扩展在自有 storage 使用同名键，互不同步）。详见 [浏览器扩展规格](./2026-09-27-browser-extension.md)。
- **未知键忽略**（便于安装程序写入额外元数据）。
- 每个请求：`Authorization: Bearer <token>`，`Accept: application/json`。
- 覆盖优先级（**均不写回** config）：
  1. CLI flag：`--config` / `--base-url` / `--token`
  2. 环境变量：`EL_CONFIG` / `EL_BASE_URL` / `EL_TOKEN`
  3. config.json（及 `EL_CONFIG` / `--config` 指向的文件）
- 缺文件 / 缺必填字段 / 无法连接服务 → 非 0 退出（见 §6）。
- HTTP 客户端默认整请求超时 **30s**；超时按连接失败处理（exit 2）。v1 **不**提供 `--timeout`。

### 2.3 全局选项

- 所有子命令可用：`--json`、`--base-url`、`--token`、`--config`、`-h` / `--help`。
- 全局：`el --version`（客户端程序集版本）。
- **`--version` / `-h` / `--help`：不读 config、不连服务**，可离线 exit 0。
- `--config` **无短选项**（避免与 `-c` = `--create` 冲突）。

## 3. 命令集与 API 映射

| 命令 | 用法（示意） | HTTP |
|---|---|---|
| `el tag` | `el tag <target> <alias>... [-c\|--create]` | `POST /v1/resources/tags`（`add`；`createMissing` ← `--create`） |
| `el untag` | `el untag <target> <alias>... [-y\|--yes]` | `POST /v1/resources/tags`（`remove`；永不 `createMissing: true`） |
| `el tags` | `el tags <target>` | `GET /v1/resources/tags?uri=` |
| `el query` | `el query <q> [--expand child] [--max-depth] [--expanded-tag-limit] [--limit] [--offset]` | `GET /v1/query` |
| `el preview` | `el preview <q> [...]`（expand/闸门同 query） | `GET /v1/query/preview` |
| `el suggest` | `el suggest <prefix> [--limit]` | `GET /v1/tags/suggest` |
| `el completion` | `el completion powershell` | 无 API；stdout 打印补全脚本 |

### 3.1 参数约定

- **单 target**：第一个位置参数是 `<target>`，其后全部是 `<alias>`。多文件由壳循环；v1 不支持一次多个 target。
- `<target>`：本机路径或 URI（§4）。
- `<alias>...`：一个或多个标签别名；`tag` / `untag` **至少 1 个**、一次最多 **100** 个（与 API `add`+`remove` 上限对齐）。缺 alias 或超出 → 本地 `bad_request`、**不发请求**。
- `query` / `preview` 的 `<q>`、`suggest` 的 `<prefix>`：**恰好一个**位置参数；含空格时由壳引用。多个位置参数 → 本地 `bad_request`。CLI **不**二次改写分词，原样作为 `q=` 提交。
- trim 后为空的 `<q>` / `<prefix>` → 本地 `bad_request`，不发请求。
- 位置参数（含负词查询）若以 `-` 开头，须使用 `--`：例如 `el query -- -archived`。
- `tag` / `untag` **不传** `resourceId`，只传规范化后的 `uri`；**不传** `displayName`（恒相当于 null）。
- **仅 `tag` 传 `kind`**（§3.2）；`untag` / `tags` 不传 `kind`。

### 3.2 `kind` 推断（仅 `tag`）

| 情况 | `kind` |
|---|---|
| `http://` / `https://` | `url` |
| 本地路径或 `file://`，解析后目标存在且为目录 | `folder` |
| 其余 `file` 情形（含存在的文件） | `file` |

符号链接：见 §4.4。

## 4. Target 解析（路径 → URI）

与[数据模型 §2](./2026-09-23-data-model.md) 一致。

### 4.1 判定顺序

1. 若以 `http://` / `https://` / `file://` 开头（大小写不敏感）→ 按 URL / file 规则规范化。
2. 否则视为本机路径：相对路径先相对**当前工作目录**解析为绝对路径，再规范为 `file:///C:/...`（盘符大写、`/` 分隔、非根去尾 `/`）。
3. **UNC**（`\\server\share\...`）→ `file://server/share/...`（host = server，无盘符盘路径形态）。

### 4.2 URL 规范化（摘要）

- `http(s)`：scheme/host 小写；省略默认端口；去掉 `#fragment`；保留 query。
- `file`：同上数据模型 file 规则；UNC 见上。

### 4.3 存在性检查

| 命令 | 本机路径 / `file://` | `http(s)://` |
|---|---|---|
| `el tag` | **必须存在**（文件或目录；见 §4.4）；否则本地失败、不发请求 | 不检查本地 |
| `el tags` | **不检查**；规范化后查 API | 不检查本地 |
| `el untag` | **不检查**；规范化后照常 `remove` | 不检查本地 |

说明：`untag` / `tags` 允许对已删除本地文件对应的 URI 操作；仅 `tag`（需推断 `kind` 并可能隐式建资源）要求目标真实存在。

### 4.4 符号链接

- **URI 身份**：按用户给出的路径规范化（**不**把身份解析成最终目标）。
- **存在性 / `kind`**：看**解析后的目标**（目录 → `folder`）。
- **断链**（link 在、目标不在）：`tag` → `path_not_found`，不发请求。

## 5. 打标、去标与查询参数

### 5.1 打标

- `el tag`：`createMissing = true` 当且仅当出现 `--create` / `-c`；默认 `false`。
- 成功人类输出：stdout 简短摘要（如 `added: …`）；若因 `--create` 新建了标，另附 `created: …`（无新建则不提 `created`）。
- `--json`：stdout 为 API 成功响应的 `data`。
- HTTP 200（含 `added` 为空的幂等无变更）→ exit 0；人类模式可打印「无变更」。

### 5.2 去标与确认

- `el untag`：永不自动建标；去掉的是**资源上的绑定**，不是删除 Tag 实体。
- **确认开关**（默认开）：
  - config `confirmUntag`（缺省 = `true`）
  - `-y` / `--yes`：本次跳过确认
  - 无反向 `--confirm` flag；持久关闭靠把 config 设为 `false`
- 当需要确认时（`confirmUntag != false` 且未带 `--yes`）：
  - **TTY**：stderr 提示，例如 `Remove alias(es) […] from <uri>? [y/N]`；仅 `y` / `Y` 继续；空回车及其它 → 取消（exit 1，不发请求）。默认 **N**。
  - **非 TTY**（管道/CI 等）：本地 `bad_request`，exit 1，stderr 提示加 `--yes`；**不**从管道读 `y` 当确认。
- `confirmUntag: false` 或带 `--yes`：直接发请求。
- 成功人类输出 / `--json` / 幂等 exit 0：同 §5.1 精神（`removed` 可空）。

### 5.3 查询 / 预览 / 建议

| CLI 参数 | 含义 | 默认 |
|---|---|---|
| （无 `--expand`） | 不传 expand；服务端按未展开 | 不展开 |
| `--expand child` | 对应 API `expand=child` | — |
| `--max-depth` | `maxDepth` | 仅 expand 时传；省略用服务端默认 **8** |
| `--expanded-tag-limit` | `expandedTagLimit` | 仅 expand 时传；省略用服务端默认 **512** |
| `--limit` | 分页 limit | `query`：**50**；`preview` / `suggest`：**10**；上限跟 API **1024** |
| `--offset` | 分页 offset | **0**（仅 `query`） |

规则：

- 未带 `--expand` 却写了 `--max-depth` 或 `--expanded-tag-limit` → CLI **本地报错**。
- `--expand` 值 v1 **仅**允许 `child`；其它值 → 本地报错。
- 闸门触顶等行为完全由 API 决定（`422 expansion_limit_exceeded` 等）。

## 6. 输出与退出码

### 6.1 输出

- **默认（人类可读）**
  - `query` / `preview`：stdout 每行一个资源（优先 `displayName`，否则 URI）。分页摘要（`offset` / `limit` / `total`）写 **stderr**。
  - API 成功信封中的非空 `message`（如未知正词 notice）→ **stderr**（一行文本）；stdout 仍可为空白列表；exit 0。
  - `tags` / `suggest`：stdout 每行一个别名；`suggest` 可在同一行附简要 `name` / `nameInitials`。
  - `tag` / `untag`：stdout 简短成功摘要（见 §5）。
- **`--json`**
  - stdout **仅**成功时的业务 JSON（API 信封中的 `data`）。
  - 与人类模式互斥；提示/摘要/分页/notice **不得**写入 stdout；notice 仍可写 **stderr**。
- **错误**
  - 默认：stderr 人类可读文本。
  - `--json`：stderr 输出 `{ "error": { "code", "message" } }`（与 HTTP 错误码对齐；本地错误见下表）。

### 6.2 本地错误 `code`

用法类场景（空参数、多位置参数、非法壳名、无 expand 却传闸门、缺 `--yes` 的非 TTY untag 确认等）**归并**为 `bad_request`，靠 `message` 区分；v1 不扩细码。

| code | 场景 |
|---|---|
| `config_missing` | 配置文件或必填字段缺失 |
| `path_not_found` | `tag` 目标路径 / `file://` 本地不存在或断链 |
| `bad_request` | 用法/校验错误（含确认被拒、非 TTY 缺 `--yes` 等） |
| `connection_failed` | 无法连接 `baseUrl` 或请求超时 |

### 6.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（含查询未知正词空列表、幂等无变更的 HTTP 200；`--version` / help） |
| 1 | 本地用法/校验失败（含 untag 确认取消） |
| 2 | 配置缺失或连接失败/超时 |
| 3 | HTTP 4xx（含 `401 unauthorized`、业务错误如 `tag_not_found`） |
| 4 | HTTP 5xx 或其它网络失败 |

## 7. 补全

- `el completion powershell`：将 PowerShell 补全脚本打印到 **stdout**。
  - **打印脚本本身**：离线即可（不读 config、不连服务）。
  - 仅参数 `powershell` 合法；缺失或其它壳名 → 本地 `bad_request`。
- 补全目标：`tag` / `untag` 的别名、`query` / `preview` 中适宜补全的标签词、`suggest` 的前缀；运行时调用 `GET /v1/tags/suggest`。
- 补全路径上服务不可达 / suggest 失败 → **静默空补全**（不打断打字）。显式子命令仍按 §6 报错。
- v1 **仅**交付 PowerShell；cmd / bash 延后。

## 8. v1 非目标

- 交互确认**建标**、TUI、打开/启动资源（`untag` 确认见 §5.2，不在此列）
- 目录递归批量打标、多 target 单次调用
- 标签 / 关系管理子命令
- 服务启停、安装、写 config（见 [配置与安装](./2026-09-27-config-and-install.md)）
- 非 PowerShell 壳补全
- `--timeout`、探活子命令、`--long` 查询列表
