## 1. 设计摘要

- `el` 为本机**薄客户端**：只调 Service HTTP，不直连 SQLite。
- v1 命令面（动词优先、扁平子命令）：`tag` / `untag` / `tags` / `query` / `preview` / `suggest` / `completion`。
- **不做**：标签 CRUD、关系管理、启停服务、装卸载、TUI、打开资源、目录递归批量打标。
- 本机路径自动规范为 `file://` URI；读 `%AppData%/EverythingLabeled/config.json`。
- 默认人类可读输出；`--json` 输出业务 JSON。默认**不** `expand`；打标默认**不**自动建标（`--create` 才建）。

## 2. 定位与连接

### 2.1 职责

| 能力 | v1 |
|---|---|
| 打标 / 去标 | ✓ |
| 查看资源标签 | ✓ |
| 查询 / 预览 | ✓ |
| 标签建议 | ✓ |
| PowerShell 补全脚本 | ✓ |
| 标签 / 关系 CRUD | ✗（直接调 API 或后续 UI） |

### 2.2 配置

启动时读取配置（默认路径：`%AppData%/EverythingLabeled/config.json`）：

```json
{
  "baseUrl": "http://127.0.0.1:5123",
  "token": "<local-secret>"
}
```

- 每个请求：`Authorization: Bearer <token>`，`Accept: application/json`。
- 可选覆盖（**不写回** config）：
  - `--config <path>`
  - `--base-url <url>`
  - `--token <token>`
- 缺文件 / 缺字段 / 无法连接服务 → 非 0 退出（见 §6）。

### 2.3 全局选项

所有子命令可用：`--json`、`--base-url`、`--token`、`--config`、`-h` / `--help`。

## 3. 命令集与 API 映射

| 命令 | 用法（示意） | HTTP |
|---|---|---|
| `el tag` | `el tag <target> <alias>... [--create]` | `POST /v1/resources/tags`（`add`；`createMissing` ← `--create`） |
| `el untag` | `el untag <target> <alias>...` | `POST /v1/resources/tags`（`remove`；永不 `createMissing: true`） |
| `el tags` | `el tags <target>` | `GET /v1/resources/tags?uri=` |
| `el query` | `el query <q> [--expand child] [--max-depth] [--expanded-tag-limit] [--limit] [--offset]` | `GET /v1/query` |
| `el preview` | `el preview <q> [...]`（expand/闸门同 query） | `GET /v1/query/preview` |
| `el suggest` | `el suggest <prefix> [--limit]` | `GET /v1/tags/suggest` |
| `el completion` | `el completion powershell` | 无 API；stdout 打印补全脚本 |

### 3.1 参数约定

- `<target>`：本机路径或 URI（§4）。
- `<alias>...`：一个或多个标签别名；`tag` / `untag` 一次最多 **100** 个（与 API `add`+`remove` 上限对齐）。超出 → 本地失败、**不发请求**。
- `query` / `preview` 的 `<q>`：整段查询串；含空格时由壳引用。CLI **不**二次改写分词，原样作为 `q=` 提交（语法见[查询语言细则](./2026-09-26-query-language.md)）。
- `tag` / `untag` **不传** `resourceId`，只传规范化后的 `uri`。

### 3.2 `kind` 推断

| 情况 | `kind` |
|---|---|
| `http://` / `https://` | `url` |
| 本地路径或 `file://`，且存在且为目录 | `folder` |
| 其余 `file` 情形（含存在的文件） | `file` |

## 4. Target 解析（路径 → URI）

与[数据模型 §2](./2026-09-23-data-model.md) 一致。

### 4.1 判定顺序

1. 若以 `http://` / `https://` / `file://` 开头（大小写不敏感）→ 按 URL / file 规则规范化。
2. 否则视为本机路径：相对路径先相对**当前工作目录**解析为绝对路径，再规范为 `file:///C:/...`（盘符大写、`/` 分隔、非根去尾 `/`）。

### 4.2 URL 规范化（摘要）

- `http(s)`：scheme/host 小写；省略默认端口；去掉 `#fragment`；保留 query。
- `file`：同上数据模型 file 规则。

### 4.3 存在性检查

| 命令 | 本机路径 / `file://` | `http(s)://` |
|---|---|---|
| `el tag` | **必须存在**（文件或目录）；否则本地失败、不发请求 | 不检查本地 |
| `el tags` | **必须存在** | 不检查本地 |
| `el untag` | **不检查**；规范化后照常 `remove` | 不检查本地 |

说明：`untag` 允许对已删除本地文件对应的 URI 去标；`tag` / `tags` 要求目标在打标/查看时真实存在。

## 5. 打标与查询参数

### 5.1 打标

- `el tag`：`createMissing = true` 当且仅当出现 `--create` / `-c`；默认 `false`。
- `el untag`：永不自动建标。
- 成功人类输出：简短摘要（如 added / removed 的别名）到 stdout；`--json` 则输出 API 成功响应的 `data`。

### 5.2 查询 / 预览 / 建议

| CLI 参数 | 含义 | 默认 |
|---|---|---|
| （无 `--expand`） | 不传 expand；服务端按未展开 | 不展开 |
| `--expand child` | 对应 API `expand=child` | — |
| `--max-depth` | `maxDepth` | 仅 expand 时传；省略用服务端默认 **8** |
| `--expanded-tag-limit` | `expandedTagLimit` | 仅 expand 时传；省略用服务端默认 **512** |
| `--limit` | 分页 limit | `query`：**50**；`preview` / `suggest`：**10**；上限跟 API **1024** |
| `--offset` | 分页 offset | **0**（仅 `query`） |

规则：

- 未带 `--expand` 却写了 `--max-depth` 或 `--expanded-tag-limit` → CLI **本地报错**（避免误以为生效）。
- `--expand` 值 v1 **仅**允许 `child`；其它值 → 本地报错。
- 闸门触顶等行为完全由 API 决定（`422 expansion_limit_exceeded` 等）。

## 6. 输出与退出码

### 6.1 输出

- **默认（人类可读）**
  - `query` / `preview`：stdout 每行一个资源（优先 `displayName`，否则 URI）。分页摘要（如 `offset` / `limit` / `total`）写 **stderr**，避免污染管道。
  - `tags` / `suggest`：stdout 每行一个别名；`suggest` 可在同一行附简要 `name` / `nameInitials`。
  - `tag` / `untag`：stdout 简短成功摘要。
- **`--json`**
  - stdout **仅**成功时的业务 JSON（推荐直接为 API 信封中的 `data`）。
  - 与人类模式互斥；提示/摘要不得写入 stdout。
- **错误**
  - 默认：stderr 人类可读文本。
  - `--json`：stderr 输出 `{ "error": { "code", "message" } }`（与 HTTP 错误码对齐；本地错误见下表）。

### 6.2 本地错误 `code`（示例）

| code | 场景 |
|---|---|
| `config_missing` | 配置文件或必填字段缺失 |
| `path_not_found` | `tag` / `tags` 目标路径或 `file://` 本地不存在 |
| `bad_request` | 用法错误、别名超过 100、无 expand 却传闸门参数、非法 `--expand` 值等 |
| `connection_failed` | 无法连接 `baseUrl` |

### 6.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功（含查询未知正词得到空列表的软成功，HTTP 200） |
| 1 | 本地用法/校验失败 |
| 2 | 配置或连接失败 |
| 3 | HTTP 4xx（业务错误，如 `tag_not_found`） |
| 4 | HTTP 5xx 或其它网络失败 |

## 7. 补全

- `el completion powershell`：将 PowerShell 补全脚本打印到 **stdout**（由用户重定向或 `Invoke-Expression` 注册到 profile）。
- 补全目标：`tag` / `untag` 的别名参数、`query` / `preview` 中适宜补全的标签词、`suggest` 的前缀；内部调用 `GET /v1/tags/suggest`。
- v1 **仅**交付 PowerShell；cmd / bash 延后。

## 8. v1 非目标

- 交互确认建标、TUI、打开/启动资源
- 目录递归批量打标
- 标签 / 关系管理子命令
- 服务启停、安装、写 config（安装与首次 token → backlog #6）
- 非 PowerShell 壳补全
