## 1. 设计摘要

- MCP 为本机**薄客户端**：与 CLI 同级；只经 Service HTTP（Bearer），不直连 SQLite。
- v1 交付：**stdio transport**（Cursor / Claude Desktop 等起子进程）；**仅 Tools**。
- 工具面与 CLI 对齐：`tag` / `untag` / `list_tags` / `query` / `preview` / `suggest`。
- **不做**：标签/关系 CRUD、Resources、Prompts、在 MCP 内启停服务或写 config。
- 工程按「先 stdio、预留 HTTP MCP」拆分：`Client` → `Mcp.Tools` → `Mcp` host；Tools 依赖 `IElApi`，v1 仅 `HttpElApi`。
- 配置与 CLI **同一 SSOT**（AppData `config.json` + `EL_*`）；成功返回对齐 CLI `--json`（仅 API `data`）。

## 2. 定位与架构

### 2.1 职责

| 能力 | v1 |
|---|---|
| stdio MCP host | ✓ |
| Tools（CLI 同级） | ✓ |
| 读 AppData config / `EL_*` | ✓ |
| HTTP MCP / `MapMcp` | ✗（预留，见 §7） |
| InProc `IElApi` | ✗（预留） |
| Resources / Prompts | ✗ |
| 标签 / 关系 CRUD tools | ✗ |

### 2.2 进程与依赖

```text
[Cursor / Claude Desktop / …]
        │ stdio (MCP)
        ▼
EverythingLabeled.Mcp          ← transport only
        │
        ▼
EverythingLabeled.Mcp.Tools    ← [McpServerTool*]；无 transport / SQLite 依赖
        │
        ▼
IElApi  （EverythingLabeled.Client）
        │
        └─ HttpElApi ── HTTP Bearer ──► EverythingLabeled.Service /v1
```

| 项目 | 职责 |
|---|---|
| `EverythingLabeled.Client` | config 加载、`IElApi`、`HttpElApi`、路径↔URI / `kind` 推断（与 CLI / Explorer **同一库**） |
| `EverythingLabeled.Mcp.Tools` | 工具方法与 Description；本地策略（如 untag `confirm`） |
| `EverythingLabeled.Mcp` | stdio host；DI 注册 Tools + `HttpElApi` |

不变量：

- Tools **不**引用 ASP.NET / SQLite；**不**直连库。
- 新路径/URI 规则只进 `Client`；禁止 MCP 私有复制一份。
- CLI 可逐步迁到同一 `Client`；**不要求**与 MCP v1 同步改完。

### 2.3 技术栈

- .NET + 官方 `ModelContextProtocol`（stdio）。
- 工具用 `[McpServerToolType]` / `[McpServerTool]` + `[Description]`（含参数 Description）。

## 3. 工具表与参数

命名：snake_case（MCP 惯例）。语义对齐 [CLI 规格](./2026-09-26-cli.md) §3–§5。

| Tool | CLI / HTTP | 主要参数 | 默认 |
|---|---|---|---|
| `tag` | `el tag` → `POST /v1/resources/tags` add | `target`, `aliases[]`, `create_missing?` | `create_missing=false` |
| `untag` | `el untag` → remove | `target`, `aliases[]`, `confirm?` | 见 §4 |
| `list_tags` | `el tags` → `GET /v1/resources/tags` | `target` | — |
| `query` | `el query` → `GET /v1/query` | `q`, `expand?`, `max_depth?`, `expanded_tag_limit?`, `limit?`, `offset?` | 不 expand；limit **50**；offset **0** |
| `preview` | `el preview` → `GET /v1/query/preview` | 同 query（无 `offset`） | limit **10** |
| `suggest` | `el suggest` → `GET /v1/tags/suggest` | `prefix`, `limit?` | limit **10** |

共用规则：

- `target`：本机路径或 URI；规范化与 `kind` 推断在 **Client**，与 CLI §3–§4 一致。
  - `tag`：本机路径 / `file://` **必须存在**（含 symlink 目标；断链 → `path_not_found`）；`http(s)` 不检查本地。
  - `untag` / `list_tags`：**不**检查本地存在性。
- `aliases`：至少 1 个、最多 **100**；trim 后空或超限 → 本地 `bad_request`，不发请求。
- 单 `target`；不传 `resourceId` / `displayName`；仅 `tag` 传推断的 `kind`。
- `create_missing`：默认 `false`；为 true 时 API `createMissing: true`。
- `expand`：仅允许 `"child"`；未传 `expand` 却传了 `max_depth` / `expanded_tag_limit` → 本地 `bad_request`。
- 闸门触顶等由 API 决定（如 `422 expansion_limit_exceeded`）。
- 查询串 `q` / `prefix`：原样提交，MCP **不**二次改写分词；trim 后空 → 本地 `bad_request`。

不做：`completion`、打开资源、多 target、目录递归批量打标。

## 4. `untag` 确认

CLI 有 TTY 确认；MCP **无交互**，用参数等价于 `--yes`。

| 条件 | 行为 |
|---|---|
| config `confirmUntag == false` | 直接 `remove` |
| `confirmUntag != false`（缺省 **true**）且未传 `confirm=true` | **不发请求**；`bad_request`，提示再次调用并设 `confirm=true` |
| 同上且 `confirm=true` | 直接 `remove` |

- Tool description 标明 destructive，并写清上表。
- `confirmUntag: false` 时多余的 `confirm=true` 无害。
- `untag` 永不 `createMissing: true`。

## 5. 配置与客户端接入

### 5.1 配置

默认路径：`%AppData%/EverythingLabeled/config.json`。

```json
{
  "baseUrl": "http://127.0.0.1:5123",
  "token": "<local-secret>",
  "confirmUntag": true
}
```

- `baseUrl`、`token`：必填，非空。
- `confirmUntag`：可选；缺省键或省略 = `true`。
- 未知键忽略。
- 每个请求：`Authorization: Bearer <token>`，`Accept: application/json`。
- 覆盖优先级（**均不写回**）：
  1. host flag（若提供）：如 `--config` / `--base-url` / `--token`
  2. 环境变量：`EL_CONFIG` / `EL_BASE_URL` / `EL_TOKEN`
  3. config.json
- 整请求超时默认 **30s**；超时 → `connection_failed`。
- MCP **不**负责安装服务、写首次 token（→ backlog 配置与安装）。

### 5.2 Cursor / 同类示意

```json
{
  "mcpServers": {
    "everything-labeled": {
      "command": "path/to/EverythingLabeled.Mcp.exe",
      "args": []
    }
  }
}
```

- 通常只配 `command`；token 走 AppData。
- 需要覆盖时用 `env`（`EL_BASE_URL` / `EL_TOKEN` / `EL_CONFIG`）。
- 服务未启动 → 工具返回 `connection_failed`；MCP **不**拉起 daemon。

## 6. 返回与错误

### 6.1 成功

- 返回 API 信封中的 **`data`**（对齐 CLI `--json`）。
- 若信封非空 `message`（如查询未知正词 notice）：须一并提供给 Agent（附在结果旁或同结构字段），**不得丢弃**。

### 6.2 失败

结构化（对齐 CLI `--json` 错误）：

```json
{
  "error": {
    "code": "bad_request",
    "message": "…"
  }
}
```

本地 `code`：

| code | 场景 |
|---|---|
| `config_missing` | 配置文件或必填字段缺失 |
| `path_not_found` | `tag` 目标路径 / `file://` 本地不存在或断链 |
| `bad_request` | 用法/校验错误（含未确认的 `untag`） |
| `connection_failed` | 无法连接 `baseUrl` 或请求超时 |

HTTP 业务错误：透传 API `data.code` + `message`（如 `tag_not_found`、`unauthorized`）。  
stdio 对 Agent **无** CLI 式 exit code 语义；成败以工具 `isError` / 上述 JSON 为准。

## 7. 预留：HTTP MCP（非 v1）

目标：日后在 Service 进程内 `MapMcp`，Tools **零改签名**。

| 步骤 | 内容 |
|---|---|
| 1 | Service 引用 `EverythingLabeled.Mcp.Tools` |
| 2 | 注册 `InProcElApi`（或同等应用层门面）实现 `IElApi` |
| 3 | `MapMcp`；鉴权与回环策略与现有 HTTP API 对齐 |
| 4 | 仅换 DI 与 transport；不改工具参数与 Description 契约 |

v1 **不**实现本小节；实现时另开规格修订。

## 8. v1 非目标

- HTTP MCP / `MapMcp` / `InProcElApi`
- MCP Resources / Prompts
- 标签 / 关系管理 tools
- 多 target、目录递归批量打标、打开/启动资源
- 在 MCP 内启停 Service、安装、写 config
- TTY 交互确认（仅 `confirm` 参数）
- 强制与 CLI 同步完成 Client 迁移（禁止双份路径规则即可）

## 9. 自检清单（实现时）

- [ ] Tools 只经 `IElApi`；stdio host 注入 `HttpElApi`
- [ ] config / env / flag 优先级与 CLI 一致；不写回
- [ ] 六工具默认与 CLI 一致（`create_missing`、expand、limit/offset）
- [ ] `untag`：`confirmUntag` + `confirm` 符合 §4
- [ ] 路径 / URI / `kind` / symlink / UNC 与 CLI §3–§4 **同库**
- [ ] 成功回 `data`；失败 `{ error: { code, message } }`；notice 不丢
- [ ] Cursor 仅配 `command` 即可（服务已启动 + AppData 有 token）
- [ ] `Mcp.Tools` 无 ASP.NET / SQLite 引用，便于日后挂 Service
